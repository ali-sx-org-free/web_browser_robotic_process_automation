一台電腦的人工驗收

PR 合併前，在一台電腦上同時跑管理 Portal、測試網站、命令列的錄製端與好幾個 Worker，照著任務紀錄的驗收步驟逐項確認。正式伺服器、它的資料與已經配對的 App 都不碰。

這個方法驗的是功能與畫面。打包的 App、兩台電腦之間的網路、Windows 上的 Worker、無桌面的 Linux 分發包，由 CI 的端到端測試涵蓋，發布前再用草稿 Release 驗（見這個方法驗不到的）。

什麼時候用

  • PR 合併前。任務紀錄的「人工驗收（建議步驟）」寫的是要看什麼；這一頁寫的是怎麼在一台電腦把環境搭起來。三種狀態分開記錄：程式碼已合併、自動測試通過、人工驗收通過（狀態與驗收紀錄）。
  • 幾個疊在一起的 PR 一次驗。後一個 PR 從前一個的分支開出來時，用最上面那個分支就包含了全部；合併時照順序。
  • 一台 Mac 最方便。Linux 桌面、Windows 也可以，命令相同（Windows 的路徑與區網位址的查法不同）。

準備

分支、依賴、新的資料夾
cd ~/code/web_browser_robotic_process_automation
git fetch origin
git switch 要驗收的分支
git pull --ff-only
git log -1 --oneline      # 要和 PR 頁面上最新的提交相同
uv sync --locked          # 依賴有變時一定要做（例如 M8 多了 cryptography）

每次驗收用一個新的資料夾，例如 ~/rpa-m8-check，底下放管理 Portal 的資料（data）、錄製端與每個 Worker 的工作資料夾。資料夾是新的，第一次啟動才會建立「測試網站自動化」並匯入範例場景；驗收中途想從頭來，停掉 Portal、刪掉 data 再啟動。

視窗配置

每個程序一個終端機視窗，都在 clone 裡執行
視窗命令為什麼這樣開
1 測試網站uv run python -m testsite在 127.0.0.1:8765。自己開一個視窗，Portal 啟動時看到 8765 上已經有測試網站就直接沿用；Portal 重啟時測試網站還在，Worker 上執行到一半的那一列不會因為連不到網站而失敗。
2 管理 Portaluv run rpa serve --host 0.0.0.0 --port 8080 --data ~/rpa-xx-check/data --worker-port 8081 --no-local-worker--no-local-worker：執行一律交給下面的 Worker，和正式環境一樣；執行、批次、組合運行的執行位置要選「遠端 worker」。--host 0.0.0.0：可以用區網位址假裝別台電腦（見下一節）。
3 錄製端uv run rpa recorder --invite '邀請' --work-dir ~/rpa-xx-check/agent-recorder --no-open在「叢集管理 › 裝置」新增錄製端、產生邀請。啟動後印出的本機網址是「錄製端網址」：用它開 Portal，錄製、逐步調試、人工登入的瀏覽器才會開在錄製端，頁首標出「透過錄製端」。
4、5 Workeruv run rpa worker --invite '邀請' --work-dir ~/rpa-xx-check/agent-worker-1（第二個用 agent-worker-2）一台 Worker 一次只跑一個執行；要驗「同時幾列」「同時執行的節點」就開兩個，各用自己的 --work-dir。之後重開不用新的邀請：uv run rpa worker --work-dir …。
6 舊版（需要時）git worktree add ~/rpa-xx-check/main-code origin/main，在那個資料夾 uv sync --locked 後執行舊版的命令驗「舊版 Worker 被提示更新」或「從舊版升級」。用 worktree，不必切換 clone 的分支。

在一台電腦上模擬好幾台、好幾個人

  • 別台電腦。用這台在區網的位址開 Portal（macOS：ipconfig getifaddr en0，沒有結果時試 en1），伺服器就把請求當成從別台來的。例如 M8 的「第一個系統管理員只能在伺服器那台建立」：用 http://區網位址:8080 開只看到說明，用 http://127.0.0.1:8080 才能建立。要先用 --host 0.0.0.0 啟動。
  • 好幾個使用者（M8 起要登入）。平常的瀏覽器視窗登入一個帳號，無痕視窗登入另一個；第三個帳號用另一個瀏覽器。同一個瀏覽器的一般視窗共用登入，127.0.0.1 上不同的埠（8080 與錄製端網址）也共用，所以用錄製端網址開時通常已經是登入的；要看「透過錄製端也要登入」就在無痕視窗開錄製端網址。
  • 同一個帳號在「別的地方」也登入。用 curl 存一份自己的 Cookie：curl -c 檔案 -H 'Content-Type: application/json' -d '{"username":"…","password":"…"}' http://127.0.0.1:8080/login，之後 curl -b 檔案 …/api/me 看那個登入還在不在（例如改密碼後應該失效）。
  • 兩台 Worker。見上表的視窗 4、5。
  • 舊版的 Worker 或 Portal。見上表的視窗 6。升級測試：舊版 Portal 用另一組埠（例如 --port 8090 --worker-port 8091）與另一個 --data 先做出資料，停掉後用新版、同一個 --data 啟動；舊版可以不加 --no-local-worker，執行就在 Portal 裡跑，不必配對。

重啟與升級

  • 視窗 2 按 Ctrl+C 停掉 Portal，按 ↑ 再 Enter 用同一個命令重開。Worker 與錄製端會短暫連不上、自動重試；配對存在各自的工作資料夾，不用重新邀請。
  • 測試網站在視窗 1，不受影響。執行到一半的執行在 Worker 上照樣跑完，Portal 起來後收回結果。
  • 換程式（例如從 main 升到要驗收的分支）一樣是停掉、在另一個資料夾或切換分支後用同一個 --data 啟動；資料表在啟動時自動遷移。

記錄結果

  • 每一步寫好「應該看到」什麼；對不上時記下網址、執行或批次編號（run-…、batch-…）與畫面。
  • 結果交給負責的 Agent 回填任務紀錄的「驗證與審閱」與「追加紀錄」：版本（提交）、環境（電腦、作業系統）、做了哪些步驟、結果與沒驗到的。沒做、跳過、取消不算通過（AGENTS.md）。
  • 和程式對不上的文件（例如按鈕名稱不同）也一起記下來。

收尾

  1. 各個視窗按 Ctrl+C，停掉 Portal、測試網站、錄製端與 Worker。
  2. 有用 worktree 時在 clone 裡執行 git worktree remove ~/rpa-xx-check/main-code，再刪掉整個 ~/rpa-xx-check。
  3. git switch main。

常見問題

看到什麼怎麼處理
8080、8081 或 8765 被佔用正式伺服器或上一次的驗收還在跑。停掉它，或改用 --port 8090 --worker-port 8091（邀請與 Agent API 的網址跟著變）。
「測試網站自動化」的卡片比預期少資料夾不是新的，或開到了別的分支的程式。停掉 Portal、刪掉 data，確認 git branch --show-current 與 git log -1 後重開。
文件與 Portal 對不上、ADR 少了最新的幾篇開到了舊的 worktree 或別的分支。看瀏覽器網址列的路徑。Portal、錄製端與 Worker 用的也是那份程式，切對分支後都要重開。
裝置一直不是「線上」看那個視窗的錯誤；邀請過期就在裝置頁重新產生。設了環境變數 RPA_WORKER_TOKEN 的視窗先 unset RPA_WORKER_TOKEN。
執行或批次一直「排隊中」執行位置選了本機（用了 --no-local-worker 就沒有本機 Worker），或 Worker 不在線上。
同時兩列沒有同時跑兩台 Worker 都要線上而且空著；也看批次清單上方的「所有批次合計同時排入」。
逐步調試或錄製的瀏覽器沒有開在錄製端用的是 127.0.0.1:8080，不是錄製端印出的網址。
一直被轉到登入頁、或換帳號後另一個視窗也換了（M8）同一個瀏覽器的一般視窗共用登入；另一個帳號用無痕視窗或另一個瀏覽器。
帳號被暫停登入（M8，輸錯 5 次）等 15 分鐘，或重啟 Portal（暫停只記在執行中的 Portal 裡）。

這個方法驗不到的

  • 打包的 App。RPA 錄製端與 RPA Worker 的安裝、第一次啟動的下載、更新：CI 的「桌面端建置」在 macOS、Windows 打包後跑端到端，發布前用草稿 Release 在真的電腦上裝一次（遠端 worker）。
  • 兩台電腦之間的網路。防火牆、區網位址、對外埠：見部署與操作。
  • Linux 無桌面伺服器。分發包的安裝與升級由 CI 的「伺服器分發包」在 Rocky 8 驗；正式環境的升級照開發環境 › 分發包。
