一台电脑的人工验收

PR 合并前，在一台电脑上同时跑管理 Portal、测试网站、命令行的录制端与好几个 Worker，照着任务记录的验收步骤逐项确认。正式服务器、它的数据与已经配对的 App 都不碰。

这个方法验的是功能与画面。打包的 App、两台电脑之间的网络、Windows 上的 Worker、无桌面的 Linux 分发包，由 CI 的端到端测试涵盖，发布前再用草稿 Release 验（见这个方法验不到的）。

什么时候用

  • PR 合并前。任务记录的「人工验收（建议步骤）」写的是要看什么；这一页写的是怎么在一台电脑把环境搭起来。三种状态分开记录：代码已合并、自动测试通过、人工验收通过（状态与验收记录）。
  • 几个叠在一起的 PR 一次验。后一个 PR 从前一个的分支开出来时，用最上面那个分支就包含了全部；合并时照顺序。
  • 一台 Mac 最方便。Linux 桌面、Windows 也可以，命令相同（Windows 的路径与区网地址的查法不同）。

准备

分支、依赖、新的文件夹
cd ~/code/web_browser_robotic_process_automation
git fetch origin
git switch 要验收的分支
git pull --ff-only
git log -1 --oneline      # 要和 PR 页面上最新的提交相同
uv sync --locked          # 依赖有变时一定要做（例如 M8 多了 cryptography）

每次验收用一个新的文件夹，例如 ~/rpa-m8-check，底下放管理 Portal 的数据（data）、录制端与每个 Worker 的工作文件夹。文件夹是新的，第一次启动才会创建「测试网站自动化」并导入示例场景；验收中途想从头来，停掉 Portal、删掉 data 再启动。

窗口配置

每个进程一个终端窗口，都在 clone 里运行
窗口命令为什么这样开
1 测试网站uv run python -m testsite在 127.0.0.1:8765。自己开一个窗口，Portal 启动时看到 8765 上已经有测试网站就直接沿用；Portal 重启时测试网站还在，Worker 上运行到一半的那一列不会因为连不到网站而失败。
2 管理 Portaluv run rpa serve --host 0.0.0.0 --port 8080 --data ~/rpa-xx-check/data --worker-port 8081 --no-local-worker--no-local-worker：运行一律交给下面的 Worker，和正式环境一样；运行、批量、组合运行的运行位置要选「远程 worker」。--host 0.0.0.0：可以用区网地址假装别台电脑（见下一节）。
3 录制端uv run rpa recorder --invite '邀请' --work-dir ~/rpa-xx-check/agent-recorder --no-open在「集群管理 › 设备」添加录制端、产生邀请。启动后印出的本机网址是「录制端网址」：用它开 Portal，录制、逐步调试、人工登录的浏览器才会开在录制端，页眉标出「通过录制端」。
4、5 Workeruv run rpa worker --invite '邀请' --work-dir ~/rpa-xx-check/agent-worker-1（第二个用 agent-worker-2）一台 Worker 一次只跑一个运行；要验「同时几列」「同时运行的节点」就开两个，各用自己的 --work-dir。之后重开不用新的邀请：uv run rpa worker --work-dir …。
6 旧版（需要时）git worktree add ~/rpa-xx-check/main-code origin/main，在那个文件夹 uv sync --locked 后运行旧版的命令验「旧版 Worker 被提示更新」或「从旧版升级」。用 worktree，不必切换 clone 的分支。

在一台电脑上模拟好几台、好几个人

  • 别台电脑。用这台在区网的地址开 Portal（macOS：ipconfig getifaddr en0，没有结果时试 en1），服务器就把请求当成从别台来的。例如 M8 的「第一个系统管理员只能在服务器那台创建」：用 http://区网地址:8080 开只看到说明，用 http://127.0.0.1:8080 才能创建。要先用 --host 0.0.0.0 启动。
  • 好几个用户（M8 起要登录）。平常的浏览器窗口登录一个账号，无痕窗口登录另一个；第三个账号用另一个浏览器。同一个浏览器的一般窗口共用登录，127.0.0.1 上不同的端口（8080 与录制端网址）也共用，所以用录制端网址开时通常已经是登录的；要看「通过录制端也要登录」就在无痕窗口开录制端网址。
  • 同一个账号在「别的地方」也登录。用 curl 存一份自己的 Cookie：curl -c 文件 -H 'Content-Type: application/json' -d '{"username":"…","password":"…"}' http://127.0.0.1:8080/login，之后 curl -b 文件 …/api/me 看那个登录还在不在（例如改密码后应该失效）。
  • 两台 Worker。见上表的窗口 4、5。
  • 旧版的 Worker 或 Portal。见上表的窗口 6。升级测试：旧版 Portal 用另一组端口（例如 --port 8090 --worker-port 8091）与另一个 --data 先做出数据，停掉后用新版、同一个 --data 启动；旧版可以不加 --no-local-worker，运行就在 Portal 里跑，不必配对。

重启与升级

  • 窗口 2 按 Ctrl+C 停掉 Portal，按 ↑ 再 Enter 用同一个命令重开。Worker 与录制端会短暂连不上、自动重试；配对存在各自的工作文件夹，不用重新邀请。
  • 测试网站在窗口 1，不受影响。运行到一半的运行在 Worker 上照样跑完，Portal 起来后收回结果。
  • 换程序（例如从 main 升到要验收的分支）一样是停掉、在另一个文件夹或切换分支后用同一个 --data 启动；数据表在启动时自动迁移。

记录结果

  • 每一步写好「应该看到」什么；对不上时记下网址、运行或批量编号（run-…、batch-…）与画面。
  • 结果交给负责的 Agent 回填任务记录的「验证与审阅」与「追加记录」：版本（提交）、环境（电脑、操作系统）、做了哪些步骤、结果与没验到的。没做、跳过、取消不算通过（AGENTS.md）。
  • 和程序对不上的文档（例如按钮名称不同）也一起记下来。

收尾

  1. 各个窗口按 Ctrl+C，停掉 Portal、测试网站、录制端与 Worker。
  2. 有用 worktree 时在 clone 里运行 git worktree remove ~/rpa-xx-check/main-code，再删掉整个 ~/rpa-xx-check。
  3. git switch main。

常见问题

看到什么怎么处理
8080、8081 或 8765 被占用正式服务器或上一次的验收还在跑。停掉它，或改用 --port 8090 --worker-port 8091（邀请与 Agent API 的网址跟着变）。
「测试网站自动化」的卡片比预期少文件夹不是新的，或开到了别的分支的程序。停掉 Portal、删掉 data，确认 git branch --show-current 与 git log -1 后重开。
文档与 Portal 对不上、ADR 少了最新的几篇开到了旧的 worktree 或别的分支。看浏览器网址列的路径。Portal、录制端与 Worker 用的也是那份程序，切对分支后都要重开。
设备一直不是「在线」看那个窗口的错误；邀请过期就在设备页重新产生。设了环境变量 RPA_WORKER_TOKEN 的窗口先 unset RPA_WORKER_TOKEN。
运行或批量一直「排队中」运行位置选了本机（用了 --no-local-worker 就没有本机 Worker），或 Worker 不在在线。
同时两列没有同时跑两台 Worker 都要在线而且空着；也看批量清单上方的「所有批量合计同时排入」。
逐步调试或录制的浏览器没有开在录制端用的是 127.0.0.1:8080，不是录制端印出的网址。
一直被转到登录页、或换账号后另一个窗口也换了（M8）同一个浏览器的一般窗口共用登录；另一个账号用无痕窗口或另一个浏览器。
账号被暂停登录（M8，输错 5 次）等 15 分钟，或重启 Portal（暂停只记在运行中的 Portal 里）。

这个方法验不到的

  • 打包的 App。RPA 录制端与 RPA Worker 的安装、第一次启动的下载、更新：CI 的「桌面端建置」在 macOS、Windows 打包后跑端到端，发布前用草稿 Release 在真的电脑上装一次（远程 worker）。
  • 两台电脑之间的网络。防火墙、区网地址、对外端口：见部署与操作。
  • Linux 无桌面服务器。分发包的安装与升级由 CI 的「服务器分发包」在 Rocky 8 验；正式环境的升级照开发环境 › 分发包。
