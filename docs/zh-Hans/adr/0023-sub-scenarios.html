ADR 0023：子场景是 DSL 的 call 步骤，子场景的固定版本跟着调用场景的版本存放

场景用 call 在同一个浏览器、同一个分页里接着运行另一个场景的固定版本：入参照子场景的契约校验，它自己的独立断言通过才把出参交回来。子场景那个版本的场景文件原样拷贝在调用场景的版本里、算进内容哈希，所以调用场景自己就能运行，通过验证的内容就是之后运行的内容。

背景

M7.1 让场景可以分支与循环，但每个场景还是从头写到尾：同一段操作（例如「创建客户」）在好几个场景里各写一次。组合场景（M6）能把场景串起来，可是每个节点各自开浏览器、各自运行，接不了「同一个画面上接着做」的流程，也不能放进循环逐笔调用。

发布门槛靠内容哈希确认「通过验证的就是要发布、要运行的版本」（ADR 0015）。如果运行时才去找子场景，子场景换版本、封存或没同步到那台服务器，调用场景的行为就会在没有新版本的情况下改变；远程 Worker 与录制端也要另外拿子场景。

决策

  • 写法是一个步骤。action: call，scenario、revision 指定子场景的固定版本，inputs 给入参，as 把出参存成事实；append: true 把每次的出参累积成清单。可以放在区块里，可以 onError: continue 或被 try 接住；不能 retry、不能写 timeout。
  • 契约照子场景自己的。入参在子场景的第一步之前照它的契约校验；它的步骤跑完后立刻跑它自己的 verify，通过才产生出参。任何一段不通过，call 这一步失败。调用场景的 verify 与发布门槛不变。
  • 同一个浏览器，各自的命名空间。子场景从 call 指定的分页接着做，用调用场景的浏览器、登录状态与总期限；事实、循环变量、分页名称与截图文件名各自独立，子场景开了没关的分页在结束时关掉。
  • 子场景文件跟着调用场景的版本。子场景那个版本的场景文件原样拷贝到 calls/<代号>/<版本>.yaml（子场景自己调用的也平放在这里），列入场景的来源文件、算进内容哈希。没有用到 call 的场景哈希不变。
  • 服务器在保存时带入。新加的 call 要引用发布过的版本（规则同组合场景的节点：场景在、没封存，版本在、没有问题、发布过）。上一个版本已经带进来的子场景不再检查：子场景之后封存或这台没有它，调用场景照样能改别的地方再存。送进来的 calls/ 文件不直接采用，这台有那个版本时一律用这台的。
  • 第一版的限制在校验时检查。子场景要是 DSL 场景；登录角色相同或不需要登录；Secrets 要在调用场景声明；不能有文件入参与出参；最多 3 层、10 个不同的子场景版本；不能绕回自己。
  • 记录依路径对应。子场景的步骤记录接在 call 后面，path 过了 "call" 是子场景里的位置；回看与报告从运行目录快照里的 calls/ 找原文。
  • 扩充 call。连同子场景自己用到的扩充一起比较；看不懂的录制端与 Worker 不会领到。schemaVersion 维持 1。

后果

  • 调用场景的版本自己就完整：远程 Worker、录制端、rpa run、领域文件夹与 git 同步都不用另外处理子场景；验证记录证明的内容包含子场景。
  • 子场景出新版本不会自动应用：每个调用场景要改 revision、存成新版本、重新验证与发布。这是刻意的（和组合场景固定节点版本相同），代价是子场景修正后要逐一更新调用它的场景；目前没有「哪些场景用到这个子场景」的清单。
  • 同一个子场景被好几个场景调用时，场景文件在每个调用场景的版本里各有一份（文字档，通常几 KB）。
  • 带进来的那一份和来源版本是否相同，只在这台有来源版本时由服务器保证；从别处同步来的领域文件夹以调用场景自己的哈希与验证记录为准，rpa pack check 不另外比较来源。
  • 逐步调试时 call 整个子场景一起运行，算有副作用；接著录制（先重播既有步骤）还不支持用到 call 的场景。
  • 子场景不能有文件入参与出参；要传文件的流程先用组合场景。

没有选的方案

方案没有选的原因
运行时才依代号与版本到服务器找子场景Worker 协定、录制端、rpa run 与 git 同步都要另外处理；子场景不见时已发布的场景运行不了；哈希不包含子场景，发布门槛证明不了实际运行的内容。
不固定版本，一律用子场景目前发布的版本子场景一发布新版本，所有调用它的场景的行为就变了，却没有新的版本与验证记录；用户已决定固定版本（D8）。
保存时把子场景的步骤展开进调用场景子场景的入参、verify 与出参的界线不见了，步骤 id 与事实名称会相撞，场景文件也不再看得出哪一段是子场景。
子场景和调用场景共用事实与变量子场景就不能单独验证与重用：它的行为会随调用的场景里刚好有什么事实而变。
子场景的出参在循环里自动变成清单和 extract 的规则不一致（M7.1 的 D3 选了明确写 append）；单次调用也会拿到清单。
