ADR 0024：資料驅動是批次執行，一列是一次一般的正式執行

上傳或貼上一張表，每一列是一組入參，每一列各正式執行一次發布過的場景版本，各有報告、出參與回看。批次記下表格、欄位對應與選項，排程每次都從資料庫重新算；結束後可以匯出結果，只重跑沒有通過的列（重跑前可以改那幾列的儲存格）。

背景

常見的需求是「同一個流程，對一份清單的每一筆各做一次」：逐筆建單、逐個帳號開通。M7.1 的 forEach 能在一次執行裡逐項做，但一筆出錯就要靠 try 接住，結果只有一份報告，事後也看不出哪一筆是哪個畫面。逐筆建單往往每一筆都要留證據，而且要能只補做失敗的幾筆。

正式執行本來就有契約校驗、報告、出參、回看、執行位置與 Agent 的上限；要的是把一張表變成很多次正式執行，並且看得到每一列的結果。

決策

  • 一列是一次一般的正式執行。批次在建立時固定場景目前發布的版本；每一列排入一次目的是 execution 的執行（runs.batch_id、batch_row），和手動執行一樣有報告、出參、回看與執行位置。Worker、錄製端與執行器不知道批次。
  • 表格存文字。貼上（Tab 或逗號分隔）或上傳 CSV、TSV、Excel（.xlsx，第一個工作表；日期依儲存格格式換成 ISO 寫法）。第一列是標題；最多 1,000 列、50 欄、5 MB，每格 10,000 字。儲存格原樣存成文字，排入前才換成入參。
  • 欄位依標題自動對應，可以改。標題和入參名稱相同（或不分大小寫、忽略空白、底線與連字號後相同）就對應；沒對應或空白的儲存格用預設值。換算：數字可以有千分位；是非接受 true／false、1／0、yes／no、是／否；清單與物件寫 JSON；寫了 {{ }} 的照原樣交給動態值；檔案入參不能從表格給值。換算後照場景的契約檢查，有問題的列標成「資料有問題」、不執行。
  • 先建立再開始。建立後是「等待開始」，可以改欄位對應與選項、看每一列的檢查結果；開始後不能再改。選項：一列沒通過時照跑或停下；同時排入幾列（1～10，實際同時跑幾列看有幾台 Worker 空著）；瀏覽器、網址、有頭／無頭、執行位置同執行表單。
  • 排程從資料庫重新算。每一次執行結束（包括排隊中被取消）就重新看這個批次：哪幾列在跑、這一輪還有哪幾列沒排、有沒有沒通過的列，補滿「同時幾列」或結束。同一個通知來兩次、伺服器重啟後都能接著走；每一列的冪等鍵是「批次-列號-第幾次」，不會重複排入。排不進去的列（例如場景被封存）記下原因、算沒有通過。
  • 「第幾輪」區分要跑的列。開始是第 1 輪，每次重跑加 1；只有被選進這一輪的列會排入、會算「沒有通過」。沒指定時重跑沒有通過的列（失敗、逾時、取消、需要登入、排不進去、資料有問題、沒有執行）；可以指定列號；重跑前可以改那幾列的儲存格（只能改原有的欄位，每次執行仍各自保留）。
  • 停下不復原。手動停下或「一列沒通過就停下」時不再排新的列，手動停下會取消排隊中與執行中的列；已經發生的外部動作不會回滾。
  • 匯出由伺服器產生。CSV（UTF-8 帶 BOM，以 =、+、-、@ 開頭又不是數字的值前面加 '，避免被當成公式）與 Excel；內容是原本的儲存格加上狀態、第幾次、執行編號、每個出參與錯誤。伺服器用標準函式庫讀寫 xlsx，不加 openpyxl。
  • Agent API 用同一套。POST /agent-api/v1/batches 的 rows 每一列是一組入參（入參名稱 → 值），建立後直接開始；任何一列有問題就整批不建立（422，列出每一列的問題）。同時排入的列算在排隊與執行中的上限裡；只看得到、停得了自己建立的批次。

後果

  • 每一列的證據和手動執行完全相同，運行清單、回看、Agent 讀運行都不用改；代價是 1,000 列就是 1,000 筆執行紀錄與執行目錄，保留規則照一般執行。
  • 批次不擋場景之後發布新版本，也不會換版本：要用新版本就建一個新批次。
  • 每一列都開一次瀏覽器、登入一次（有登入角色時用保存的登入狀態）；同一個畫面裡逐項做、要共用一個瀏覽器的情況仍用 forEach。
  • 「同時幾列」只決定排入多少；同一台 Worker 一次一列，要真的平行需要多台 Worker。
  • 伺服器多兩張表（batches、batch_rows）與 runs 的兩個欄位，要一個資料庫遷移（0018）。
  • 自己讀寫 xlsx 只處理常見的情況（第一個工作表、共用字串、內嵌字串、數字與日期格式）；公式取 Excel 存下的計算結果，沒有存結果的公式讀成空白。
  • 第一版只有發布過的場景；組合場景（專案裡的組合）的批次執行、排程觸發與「批次之間共用的上限」之後再看需求。

沒有選的方案

方案沒有選的原因
只做 forEach，把表格讀成清單在一次執行裡逐列做一列出錯會影響整次執行，只有一份報告，不能只補做失敗的列；使用者選了批次執行（D9）。
批次是一種新的執行目的，或在 Worker 端逐列執行報告、回看、執行位置、Agent 的上限與運行清單都要另外處理；Worker 協定要改。
建立時就把每一列換算好存成入參改欄位對應或改儲存格就要重算、存兩份；換算規則改了以後舊批次看不出原本的資料。
用「開始之後建立的執行」判斷這一輪的結果重跑指定的列時，沒被選、也從來沒跑過的列分辨不出來，會跟著被排入；上一輪排不進去的列也會讓「一列沒通過就停下」立刻停下。
伺服器加 openpyxl 讀寫 Excel分發包的 Python 依賴改變，runtime 編號跟著變，升級要下載完整安裝包；需要的只是讀第一個工作表的文字與寫一張簡單的表。
在瀏覽器裡解析檔案、產生匯出Agent API 也要同樣的檢查與匯出；規則只寫一份在伺服器。
