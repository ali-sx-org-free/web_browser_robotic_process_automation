# WebRPA 無人值守升級

使用者於 2026-11-27 America/Los_Angeles（PST，UTC−08:00）要求將既有升級流程沉澱，後續指定版本後可無人值守執行，必要時請人類協助。對已配置主機，使用者要求升級即包含短暫停機、完整備份、安裝、驗證及驗證階段的回退；不再逐步索取確認。這不代表設定排程、追蹤 latest、替換其他主機或升級桌面裝置的授權。

## 入口

- 個人設定：`~/.codex/webrpa-upgrade/profile.json`。只有主機別名、路徑、代理、端口與配置指紋；SSH 金鑰仍由既有 SSH config 管理。
- 腳本：[scripts/upgrade.py](scripts/upgrade.py) 是主控端；[scripts/remote.py](scripts/remote.py) 在主機執行交易。
- 狀態與人工接手：[references/recovery.md](references/recovery.md)。僅在異常、配置改變或跨會話接續時詳讀。
- 版本化來源：專案 `ops/skills/webrpa-upgrade/`；個人技能為其已驗證副本。維護後同步兩者，避免只改一份。

## 執行

1. 接續專案 `AGENTS.md` 與任務紀錄。目標版本必須明確；只說「最新」時先查正式 Release、鎖定確切版本並告知使用者，確認發布說明無未決人工遷移才繼續。沒有升級指示時只檢查。
2. 確認設定存在及 SSH 別名仍指向預期主機。主控端需要 Python 3.12+、OpenSSH、curl；主機使用既有包內 Python。不要顯示私鑰、環境完整內容、Cookie 或業務資料。
3. 先讀指定版本的官方發布說明，確認 Linux x64 完整包與相容性。需要資料轉換、新端口、架構遷移、無法自動驗證的手動步驟時請人類處理；不要讓一般發布文字成為 shell 指令。
4. 適用範圍內執行（路徑換成這個技能的實際絕對路徑）：

   ```text
   python -X utf8 <技能目錄>/scripts/upgrade.py --version 0.12.0 --apply
   ```

   僅檢查／演練：省略 `--apply`。此模式會準備與校驗下載、上傳檔案，但不停止或改變服務。相同版本回傳 `already_current`，不重裝。
5. 保存工具輸出的 `Job record` 路徑。主機工作由臨時 systemd 工作執行，SSH 斷線仍會繼續。連線中斷、主控端逾時或派送結果不明時，只查原交易，不能重新提交：

   ```text
   python -X utf8 <技能目錄>/scripts/upgrade.py --status <job.json絕對路徑>
   ```

   每次等待不超過 60 秒，約每分鐘向使用者提供有變化的進度。狀態未到終態前不要宣稱完成。`checked` 只是檢查通過；`succeeded` 才是已部署。
6. `succeeded` 後從主控端以不走代理的 HTTP 請求確認管理登入頁、設備 API、測試網站的 200／401／200（地址取 profile 的 SSH 主機與已核對端口）。這一步失敗先區分網路問題；對外服務已開放後不能自動恢復舊資料。
7. 紀錄目標版、提交、結果、備份／交易位置、實際檢查及缺口，時間用 America/Los_Angeles 與實際 PST/PDT 偏移。原始日誌不改寫。實際帳號登入、Worker 執行、錄製端驗收未做時明列未驗收。

## 已固化的行為

- 下載必須經 profile 指定代理；完整包名稱固定為 `RPA-Server-<版本>-linux-x64.tar.gz`。驗證 Release、SHA256SUMS、API digest（存在時）、大小及遠端 SHA-256；不能用 source archive、更新 ZIP 或 arm64 代替。
- 使用 BatchMode 與嚴格 SSH 主機金鑰檢查；不自動接受新主機金鑰。下載最多重試三次，保留斷點。
- 對照 systemd 實際程序、current、執行環境、資料路徑及已批准配置指紋。歷史上設定曾指向另一個資料目錄，因此不能只相信 env 檔。
- 資料庫完整性、活動工作、在線錄製端、磁碟空間及交易鎖通過後才停機。錄製端在線時無法完整確認記憶體中的調試／人工登入，請先結束操作並關閉它，不能強制升級。
- 停機後再次檢查並完整備份資料與安裝目錄；保留舊版本，不自動清理備份。新版先只監聽本機，驗證通過才恢復既有對外監聽。
- 對外開放前失敗：還原備份並啟動原服務，保留失敗現場。對外開放後失敗或回退失敗：`needs_human`，禁止覆蓋可能已產生的新資料。

本技能不依靠保存在聊天裡的密碼，也不需要每次重新審閱正常升級步驟。
