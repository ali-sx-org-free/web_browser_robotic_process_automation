M8.1 登入角色與 Secrets 的使用權限

登入角色與 Secrets 綁定到帳號與 API 用戶端：只有綁定的才看得到、用得到。接在 M8 多用戶與治理 後面；設計記在 ADR 0026。

決定與實作選擇

#事項內容
G1綁定的對象登入角色與 Secrets 各自綁定到帳號、API 用戶端（已確認）。資料表 credential_grants：種類（role、secret）、對象（登入角色代號、Secret 名稱）、誰（user:帳號 id、client:用戶端代號）。
G2誰管綁定登入角色：所在領域的管理員與系統管理員；全域的登入角色與 Secrets：系統管理員（建議，已同意）。不能自己認領。
G3看得到登入角色：綁定的帳號、能管綁定的人；Secrets 的名稱：綁定的帳號、系統管理員。API 用戶端的清單也只列綁定的。
G4用到的地方都檢查場景的登入角色與 Secrets（子場景必須用同一個角色、Secrets 宣告在呼叫的場景，所以看呼叫的場景就夠）：存檔、發布、驗證、執行、重跑、批次（建立、開始、重跑、每排一列）、組合運行（開始、每個節點）、逐步調試、錄製（選了登入角色、接著錄製）。登入角色本身：人工登入、登出、檢查要已綁定而且在領域至少是執行者；修改、刪除要已綁定而且是編輯者；自動登入用到的 Secrets，存檔的人要已綁定。用登入角色自動登入時，不必另外綁定它用到的 Secrets。
G5跨領域的登入角色（實作時調整）評估時建議「場景只能用同一個領域或全域的登入角色」（使用者同意）。實作時發現 ADR 0015 本來就讓場景跨領域引用登入角色（M11 遷移把別的領域記成 requires），加這條會打破既有資料；而綁定已經擋住原本的問題（能不能用由登入角色所在領域的管理員決定）。所以不加，寫進 ADR 0026 的後果，交付時告訴使用者。
G6背景排的執行看誰批次與組合運行記下開始的人（新欄位 user_id；API 用戶端用原有的 client_id），之後排的每一列、每個節點用他檢查：中途取消綁定，還沒開始的列與節點失敗。沒有人的背景工作（git 同步、匯入範例、錄製轉換）不檢查使用者，執行時仍檢查 G5。
G7系統管理員不受綁定限制，能看能用全部，照 M8 留稽核紀錄（建議，已同意）。
G8新建的登入角色建立的人自動綁定。
G9升級第一次啟動時，把現有的 API 用戶端綁到它可用領域裡的登入角色與所有 Secrets，記進稽核紀錄；只做一次（建議，已同意）。帳號不自動綁定（v0.9 升級上來只有第一個系統管理員）。
G10刪除時刪除登入角色、Secret、API 用戶端時一併刪除綁定。
G11沒存在 Portal 的 Secret實作時補的：綁定只管存在 Portal 的 Secrets。場景宣告了但 Portal 沒存的名稱，值由執行那台電腦的環境變數提供（M2 起的做法），不必綁定；否則這類 Secret 沒地方指定，只剩系統管理員能用。寫進 ADR 0026 的後果。

人工驗收步驟（一台電腦，約 60 分鐘）

沿用一台電腦的人工驗收的做法：平常的視窗登入 admin，無痕視窗輪流登入其他帳號；新帳號的密碼都用 check-pass-1。執行位置一律「本機」（不必配對 Worker）。全部用新的資料夾 ~/rpa-m81-check。

準備：用 main 做出升級前的資料，再換成這個分支

  1. 視窗 1（clone 裡）：uv run python -m testsite，一直開著。
  2. 視窗 2：git worktree add ~/rpa-m81-check/main-code origin/main，進去 uv sync --locked，uv run rpa serve --port 8080 --worker-port 8081 --data ~/rpa-m81-check/data。瀏覽器開 http://127.0.0.1:8080 建立 admin。
  3. 「管理後台 › API 用戶端」新增 check-agent，權限範圍勾「讀領域、場景…」「交給 Worker 驗證…」「讀運行…」，複製金鑰。「場景管理 › 登入與憑證」新增 Secret TESTSITE_PASSWORD，值 user-pass。視窗 2 按 Ctrl+C。
  4. 視窗 2 回到 clone：git switch feat/m8-1-credential-grants && git pull --ff-only && uv sync --locked，再用同一個 rpa serve 命令（同一個 --data）啟動。
  5. admin：新增帳號 dana、eddie、amy，在「測試網站自動化」的「成員」分別給管理員、編輯者、執行者。

A. 升級時，既有的 API 用戶端自動綁定

  1. admin 開「登入與憑證」。應該看到「測試網站：一般使用者」「測試網站：主管」與 TESTSITE_PASSWORD 都有「誰能用（1）」；點開是 API 用戶端 check-agent。
  2. 「稽核紀錄」有一筆「升級：既有的 API 用戶端自動綁定」。重啟 Portal 後不會再多一筆（只做一次）。

B. 登入角色要綁定才看得到、用得到

  1. admin：「測試網站：一般使用者」按「登入」，在開出來的視窗用示範帳號 user 登入（密碼寫在測試網站的登入頁），按「完成登入」。
  2. 無痕視窗用 amy 登入，開「登入與憑證」。應該看到說明「這裡只列出你被指定使用的登入角色與 Secrets…」，登入角色與 Secrets 都是空的。
  3. amy 開 BA-004 的場景頁。應該看到「執行前要準備」有「沒有使用權限：登入角色 testsite-user」。按「驗證」（本機）。應該看到「「amy」還沒被指定使用登入角色 testsite-user：請它所在領域的管理員在「登入與憑證」的「誰能用」加上」，沒有排入。
  4. amy 直接開 http://127.0.0.1:8080/api/roles/testsite-manager。應該看到 404：沒綁定的登入角色連存不存在都看不到。
  5. 換 dana 登入「登入與憑證」。應該看到兩個測試網站的登入角色都有「誰能用（1）」（她是這個領域的管理員）；Secrets 是空的（沒綁定，也不能指定）。「測試網站：一般使用者」的「誰能用」：種類「帳號」、填 amy、按「加上」。
  6. 換 amy。應該看到「登入與憑證」只有「測試網站：一般使用者」，沒有「誰能用」按鈕；BA-004 驗證通過；BA-005（主管）驗證仍被拒絕。
  7. 換 dana，在同一個對話框把 amy「移除」。換 amy，BA-004 驗證又被拒絕。

C. Secrets 要綁定才用得到，只有系統管理員能指定

  1. admin 在「測試網站自動化」建立 secret-check，場景檔照 M8 驗收教程第七步 B（宣告 secrets: [TESTSITE_PASSWORD]）存成 v2。
  2. amy 開 secret-check。應該看到「沒有使用權限：Secret TESTSITE_PASSWORD」；驗證被拒絕（「還沒被指定使用 Secret TESTSITE_PASSWORD：請系統管理員…」）。
  3. eddie 「編輯場景檔」在 description 後面加幾個字存檔。應該看到同樣的訊息，存不進去：編輯者也要綁定才能存用到這個 Secret 的版本。
  4. admin：TESTSITE_PASSWORD 的「誰能用」加上 amy。amy 重新整理：「登入與憑證」看得到 TESTSITE_PASSWORD（「更換」「刪除」仍會被拒絕），secret-check 驗證通過。

D. 新建的登入角色綁定給建立的人

  1. eddie 在「登入與憑證」按「新增角色」：代號 check-role、名稱「驗收角色」、登入網址 http://127.0.0.1:8765/login、已登入時看得到 { testId: current-user }、領域「測試網站自動化」。應該看到清單裡有它。
  2. admin：check-role 是「誰能用（1）」，裡面是 eddie。

E. API 用戶端也要綁定

  1. 終端機：KEY='check-agent 的金鑰'、API=http://127.0.0.1:8081/agent-api/v1，curl -s -X POST "$API/scenes/ba-004/revisions/1/validate" -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' -d '{"inputs":{}}'。應該看到排入（有執行編號）：升級時自動綁定的照樣能用。
  2. admin 新增 API 用戶端 new-agent（同樣三個權限範圍），用它的金鑰跑同一個命令。應該看到 "code":"login_role_forbidden"。
  3. dana 在「測試網站：一般使用者」的「誰能用」加上種類「API 用戶端」、new-agent。再跑一次：排入。
  4. admin 刪除 new-agent。應該看到「測試網站：一般使用者」的「誰能用」裡沒有 new-agent 了。

F. 系統管理員不受限制，但都有紀錄

  1. admin（沒有綁定任何東西）驗證 BA-005。應該看到沒有被拒絕（主管沒登入時結果是「需要登入」）。
  2. 「稽核紀錄」有 dana 的 POST／DELETE /api/roles/testsite-user/grants、admin 的 POST /api/secrets/TESTSITE_PASSWORD/grants，以及 amy、eddie 被拒絕的請求（403）。

收尾：各視窗 Ctrl+C；git worktree remove ~/rpa-m81-check/main-code，刪掉 ~/rpa-m81-check。沒存在 Portal、由電腦的環境變數提供的 Secret 不必綁定（G11），由自動測試涵蓋；批次、組合運行中途取消綁定（G6）也由自動測試涵蓋。
