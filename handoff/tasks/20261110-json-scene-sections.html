原因

  • 段落是用行切的：editing.find_block 找「第一欄開始的 key:」那一行。JSON 寫法沒有這種行（整份只有一行 {"schemaVersion":1,…}），所以 section_text 四段都回傳空字串，場景頁的腳本與入參、出參原文是空的。表格是用解析後的資料畫的，看起來正常。
  • 存檔接在後面：replace_section 找不到段落就把新段落（YAML 區塊寫法）加在檔案最後，變成「一行 JSON＋inputs:…」，YAML 讀到第二個文件開頭的鍵報 expected '<document start>'；問題換算成段落行號時剛好是第 1 行。
  • 功能本身正常：JSON 是合法的 YAML，load_yaml 讀得懂，所以執行、驗證沒有問題。

進度、決定與下一步

  • 已完成：json_document 判斷整份是不是 JSON 物件（重複的鍵、NaN 不算，交給校驗說明）；JSON 場景檔的段落原文是只有那個鍵的 JSON 物件（縮排兩格），存檔把那個鍵的值換掉、整份照原本的寫法（壓成一行、或原本的縮排與 CRLF）寫回，鍵的順序不變，新增的段落位置和 YAML 相同；段落寫 YAML 也收。入參改名在 JSON 資料的字串值裡改（inputs["舊名"] 在 JSON 原文裡有跳脫的引號，用原文的正規表示式改不到）。錄製接在既有 JSON 場景後面時，項目讀成資料接在清單或物件後面。YAML 場景檔收到 JSON 寫法的段落時轉成區塊寫法。讀不懂的段落拋出 SectionError，伺服器回 422，問題附段落裡的行號；校驗問題的段落行號在 JSON 場景檔改用資料路徑在段落原文裡找。場景頁：腳本區標「JSON」、提示說明 JSON 寫法；契約工作台的原文標籤是「JSON 原文」，表格切到原文與存檔用 format: "json"；「插入檢查」在 JSON 斷言腳本裡加一個物件，原文不是正確 JSON 時提示先修正。
  • 決定（實作選擇）：JSON 場景檔不自動轉成 YAML、也不自動排版成多行：只改被編輯的那個鍵，其他內容的寫法照舊，和 YAML「其他行一個字都不動」的原則一致。段落原文用 {"steps": …} 而不是只放值，和 YAML 的段落以 steps: 開頭對應，貼回去時也能檢查鍵對不對。
