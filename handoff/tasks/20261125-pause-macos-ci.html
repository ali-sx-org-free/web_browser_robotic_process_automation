進度、決定與下一步

  • 已完成：macos_enabled 依事件與倉庫變數決定要不要跑 macOS；plan 把 macOS 工作標成暫停（不放進矩陣、不查通過紀錄，摘要表格照列）；每晚完整測試的矩陣拿掉 macOS；每個流程輸出 macos，一鍵安裝腳本的從零開始與每晚的 macOS 程式碼層檢查用它判斷。文檔新增 macOS 暫停 一節。
  • 為什麼：ci-metrics 分支 2026-11-10～25 的紀錄（每個工作的時間無條件進位到分）換算成 30 天：macOS 約 3,945 分、Linux 約 5,563 分、Windows 約 3,682 分。以 GitHub 價目表（2026-11-25 查證：Linux 0.006、Windows 0.010、macOS 0.062 美元／分）計，macOS 約 245 美元、Linux 約 33 美元、Windows 約 37 美元。macOS 的大頭是每晚完整測試（約 1,960 分）與一鍵安裝腳本的排程（約 1,160 分）。
  • 未完成／阻礙：(1) 暫停 macOS 後 Linux 與 Windows 每月仍約 70 美元，超過 Pro／Team 每月 18 美元的內含額度；其中排程約 48 美元（每晚完整測試約 31、一鍵安裝腳本約 17），PR 與推送約 20 美元。要壓到額度內還得降低排程的頻率，待使用者決定。(2) 倉庫改成私有後，一鍵安裝腳本的「從零開始」從 raw.githubusercontent.com 下載腳本、匿名 git clone，私有倉庫兩者都會失敗，排程每天會開 ci-schedule issue；文檔裡的一行安裝命令也只有能讀取倉庫的人能用。未處理。
  • 決定：暫停 macOS、之後可能再開（使用者明確決定，見決定）。實作選擇（Claude）：用倉庫變數而不是改 workflow，恢復不必改程式；發布照建 macOS（錄製端只有 macOS 版，發布少了 DMG 會失敗）；手動觸發明確選了 macOS 照跑，方便臨時補測。
  • 下一個具體動作：使用者審閱、合併 PR。之後要恢復時在倉庫 Settings › Secrets and variables › Actions › Variables 新增 ENABLE_MACOS_CI＝true（或 gh variable set ENABLE_MACOS_CI --body true）。
