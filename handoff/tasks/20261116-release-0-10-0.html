  • 和 v0.9.1（ab15ce6）的差異就是上面 13 個 PR。第三方依賴：rpa-server 直接依賴 cryptography>=50.0.2（M8，Secrets 加密）；uv.lock 其他的第三方套件版本不變。資料庫遷移 0018～0021（批次、組合場景的批次、多用戶、使用權限）在新版本啟動時執行。
  • 升級時要注意（從 v0.9.1，也就是目前已發布的最新版）：
    • 伺服器分發包預期要用完整的安裝包（多了 cryptography，M8 的決定 D3 已接受）；RPA Worker 與錄製端能不能只用更新檔，以發布流程比較環境代號的結果（Release 說明的「從 v0.9.1 升級」）為準。
    • 升級前照設定文件備份整個資料目錄；升級後 secrets.key 要和資料一起備份，少了它已存的 Secrets 解不開。
    • 升級後一律要登入。第一個系統管理員只能在伺服器那台（127.0.0.1）的頁面建立，或用 rpa user create 帳號 --admin。裝置配對與 Agent API 金鑰照舊。
    • 升級第一次啟動時，既有的 API 用戶端自動綁到它可用領域的登入角色與所有 Secrets（只做一次，記稽核）；其他帳號要由管理員在「登入與憑證」的「誰能用」指定（Secrets 只有系統管理員能指定）。
    • 用到新流程欄位（M7.1）的場景，v0.9.x 的 Worker 與錄製端看不懂，會提示更新；用到 call（M7.2）的場景不會派給 v0.9.x 的 Worker。
    • 簽章私鑰沿用 2026-10-25 那把，keys.py 不變。
