決定

七項的範圍由使用者 06:12 的要求決定（Claude 06:19 列出範圍時沒有收到異議）。下面是這次的實作選擇（沒有另外問使用者，審閱時可以改），理由見 ADR 的「後來的變更」：

#項目選擇
W1流程範例的匯入伺服器多一個「另外的範例資料夾」（RPA_EXTRA_EXAMPLES，以 os.pathsep 分隔，空字串是不要），預設是 scenarios/examples/flow；第一次啟動時和 BA 範例一起匯入「測試網站自動化」。分發包帶上這個資料夾，啟動腳本設好環境變數；更新時的子程序不繼承它。
W2運行頁的提醒步驟紀錄裡 handled 是 continued 或 caught 的步數；有的時候在運行頁上方顯示，說明結果仍由獨立斷言決定、要看哪幾步去執行報告或回看。
W3接著錄製用到 call 的場景伺服器把版本的 calls/ 包成 JSON 交給錄製器（--calls，和逐步調試相同），錄製器放回場景檔旁邊再校驗；只接受 calls/ 底下、沒有 .. 的路徑。版本用到的擴充改用版本自己的（含子場景）。
W4子場景的檔案入參與出參檔案入參一律由 call 用 {{ }} 給：呼叫場景自己的檔案入參（依 sha256 與檔名找回準備好的檔案），或共用工作資料夾裡的檔案（download 的事實、前一個子場景的檔案出參）。直接寫附件、路徑、上傳檔不行；子場景的預設檔案不帶過來。檔案出參要在共用工作資料夾裡，換成 {"workspace", "name", "size", "sha256"}。不加新的擴充（call 還沒發布）。
W5組合場景的批次每一列一次組合運行（目的 execution，版本在建立時固定）；表格給的是沒有接上游出參的節點入參，名稱「節點代號.入參」，標題只寫入參名稱、只有一個節點有時也自動對應；固定值當預設值。給的值存在 workflow_runs.inputs，從失敗的節點繼續時照用。不能指定網址、不能給檔案入參。遷移 0019。取消組合運行時在鎖外面取消節點的執行，避免和批次排組合運行互等。
W6選工作表POST /api/batch-sheets 列出工作表，建立批次時寫 sheet；表單只在有好幾個工作表時顯示；來源寫成「檔名 › 工作表」。
W7共用的上限設定 batches.sharedLimit（1～100，預設 10），算排隊中與執行中的批次執行和執行中的組合運行；一列結束時先排同一個批次，再依開始的先後補其他批次，調高時馬上補。設定在批次清單上面，API 是 /api/settings/batches。

人工驗收（建議步驟，未執行）

  • 流程範例：用新的資料夾啟動（uv run rpa serve --data data-check）：「測試網站自動化」裡除了 BA 範例還有六個 flow- 開頭的場景。
  • 運行頁的提醒：驗證 flow-optional-survey（有 onError: continue 的步驟）：運行頁上方出現「有 N 步失敗後繼續」，結果仍是通過。
  • 接著錄製：新增一個場景，在編輯頁「插入流程範本」插入 call 的範本、改成呼叫 BA-001 第 1 版（BA-001 要先發布）存檔，按「接著錄製」：先重播，子場景的步驟照樣在同一個分頁跑完，接著可以錄製。
  • 子場景的檔案：寫一個呼叫場景：有自己的檔案入參，call 一個有檔案入參、會上傳的子場景（例如照 scenarios/examples/browser-python/upload-summary.yaml 寫），inputs 寫 '{{ inputs.檔案 }}'；執行通過，網頁收到的就是那個檔案。把值改成 files/a.csv 存檔，回 422 並說明要寫 {{ }}。
  • 組合場景的批次：BA-001 → BA-002 的組合場景驗證並發布後，組合場景頁按「批次執行」，貼上 title 一欄三列（其中一列空白）；批次頁的欄位對應是 n1.title ← title，開始後每一列一次組合運行，空白那一列用節點的固定值；執行編號連到組合運行的匯總報告，出參欄有 n2.recordId。
  • 選工作表：上傳一個有兩個工作表的 .xlsx：表單出現「工作表」，選第二個建立，欄位是第二個工作表的標題，來源顯示「檔名 › 工作表」。
  • 共用的上限：批次清單上面把上限改成 1，建兩個「同時 2 列」的批次並開始：合計只有一列在排隊或執行，第一個批次跑完才輪到第二個；改回 10 時第二個批次馬上補滿。
