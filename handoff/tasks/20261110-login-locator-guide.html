做法

  • 在瀏覽器裡點選：表單填好登入網址按「打開瀏覽器」→ POST /api/locator-picks（角色還不用存）→ 在操作的那台（Portal 這台或錄製端）啟動 python -m rpa_runner.login pick，和人工登入一樣開有頭視窗到登入網址。使用者登入後按「開始點選」，子程序在每個分頁放點選層（換頁後重放）：滑過的元素框起來，點一下記下那個元素與往上幾層，點擊不傳給網頁。依點到的元素與往上兩層產生寫法（測試代號 → 角色與名稱 → 文字 → title → alt → 穩定的 #id），每一種用執行時同一套 resolve 在頁面上找：找不到的不列，只有一個、看得到的排前面。表單列出寫法與找到幾個；「使用這個」填入，確認網址沒填時換成點選時的網址。填入、關掉表單、離開頁面或閒置 15 分鐘時關掉視窗；同時最多 4 個。
  • 自己填：選種類（頁面上的文字、按鈕、連結、測試代號、CSS）與看到的內容，產生一行定位器（需要時加引號，例如 { css: "#user-menu" }）。沒有圖形介面時用這個。
  • 相容：錄製端的 App 回報能力 loginPick；舊的 App 沒有時說明要更新錄製端（沿用 RecorderHub.require）。點選的子程序在錄製端的允許清單 rpa_runner.login 裡，不用改錄製端的清單。
  • 決定（實作選擇）：點選視窗不存登入狀態、不和人工登入合併：角色要先有「已登入時看得到的元素」才能確認登入，合併會讓角色在沒有判斷依據時存下登入狀態。代價是新角色要登入兩次（點選一次、存登入狀態一次）。
